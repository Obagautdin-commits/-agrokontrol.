# AgroKontrol 1.0 — инструкция от начала до конца

Готовый исходный код адаптивной CRM для обслуживания теплиц. Используется на iPhone, Android, Mac и Windows через браузер. Интерфейс на русском. Все финансовые суммы в ₽.

**Что реализовано:**
- Вход по личной электронной почте и паролю для администратора и агронома. Общедоступной регистрации нет.
- Администратор создаёт и редактирует клиентов, архивирует их, записывает оплаты, старые долги и расходы.
- Агроном видит клиентов, платежи и задолженности; может планировать и отмечать визиты, фиксировать факт консультации.
- Площадь × тариф = сумма за месяц, сохраняемая в начислении. Деление на число визитов (по умолчанию 4).
- Ведение частичных, недельных и полных оплат наличными или переводом. Защита на уровне базы от оплаты больше начисления.
- Начисления на новый месяц кнопкой «Начислить месяц» с сохранением исторических тарифов.
- Автопланирование оплаченных визитов на выбранную неделю: учёт оплаченных долей, района, предпочтительного дня и уже назначенных посещений.
- Ручной календарь, редактирование статуса визита, учёт консультаций, группировка маршрута по районам.
- Отчёты по месяцам/годам, график поступлений, долги прошлых месяцев и сезонов, расходы, чистый денежный поток.
- Выгрузка JSON и CSV, журнал аудита изменений, отдельные права доступа через PostgreSQL RLS.

**Ограничения v1:** настоящая оптимизация автомобильного маршрута с картой и оценкой пробок, SMS, автоматические резервные копии сервера и восстановление JSON внутри интерфейса пока не реализованы. Автопланировщик использует 30-минутные интервалы, НЕ рассчитывает дорогу; всегда проверяйте расписание. Автопланирование не запускается само в понедельник — нажимается кнопкой. Это рабочая первая версия после настройки инфраструктуры, а не публично размещённый сайт.

## Вариант без программирования: загрузить в GitHub через браузер

### Шаг 1. Скачать архив
1. Получите `AgroKontrol.zip` из ChatGPT.
2. На Mac/Windows откройте папку «Загрузки» / Downloads.
3. Распакуйте архив двойным нажатием (или «Извлечь всё»).
4. Убедитесь, что внутри папки `AgroKontrol` есть `package.json`, `index.html`, папки `src` и `supabase`. **В GitHub нужно загрузить содержимое этой папки, а не один ZIP.**

### Шаг 2. Создать безопасную базу Supabase
1. Откройте https://supabase.com/dashboard и войдите / зарегистрируйтесь.
2. Нажмите **New project**. Название `agrokontrol-db`. Выберите регион близко к вашей работе. Придумайте пароль базы и сохраните его отдельно (не присылайте его в чат).
3. Когда проект создан, слева выберите **SQL Editor** → **New query**.
4. Откройте файл `supabase/schema.sql` из скачанной папки обычным текстовым редактором. Скопируйте весь текст в окно SQL Editor.
5. Нажмите **Run**. Скрипт создаёт таблицы `profiles`, `clients`, `charges`, `payments`, `visits`, `expenses`, `audit_log`, связи, триггеры проверки и RLS-политики.
6. Если появляется ошибка, НЕ продолжайте записывать реальные персональные данные, пока ошибка не исправлена.

### Шаг 3. Добавить 2 учётные записи
1. В проекте Supabase откройте **Authentication → Users**.
2. Нажмите **Add user** (или **Create user**) и создайте пользователя с **вашей личной почтой** и сильным новым паролем. При наличии настройки подтверждения почты подтвердите адрес.
3. Повторите для второго агронома с **другой почтой и другим паролем**.
4. Скопируйте у каждого пользователя поле `UID` — уникальный идентификатор из 36 символов.
5. Откройте **SQL Editor → New query**. Вставьте следующую команду, заменяя только строки в кавычках на соответствующие UID:

```sql
insert into public.profiles (id, display_name, role)
values
 ('ВСТАВИТЬ-UID-АДМИНА', 'Администратор', 'admin'),
 ('ВСТАВИТЬ-UID-АГРОНОМА', 'Агроном', 'agronomist')
on conflict (id) do update
set display_name=excluded.display_name, role=excluded.role;
```

6. Нажмите **Run**. Роли записаны. Никогда не используйте один общий пароль для двух сотрудников. Не регистрируйте публичный аккаунт «для всех».

### Шаг 4. Взять две публичные настройки Supabase
1. В Supabase нажмите **Connect** в верхней части проекта или откройте **Project Settings → API Keys** (названия могут меняться).
2. Найдите **Project URL**, например `https://abc123.supabase.co`.
3. Найдите **Publishable key** (может начинаться с `sb_publishable_...`), либо legacy `anon` key. Это публичные клиентские ключи, безопасность данных обеспечивается RLS.
4. **Ни в коем случае не копируйте `service_role`, `secret key`, пароль базы или личные пароли в Vercel-переменные с префиксом VITE, в GitHub или в переписку.**
5. Для приложения нужны ровно две переменные: `VITE_SUPABASE_URL` и `VITE_SUPABASE_PUBLISHABLE_KEY`.

### Шаг 5. Загрузить исходники на GitHub
1. Откройте на компьютере https://github.com и войдите.
2. Откройте свой пустой репозиторий (или создайте **New repository**, название `agrokontrol`, режим **Private** рекомендован для исходного кода CRM).
3. Нажмите **Add file → Upload files**. Если репозиторий совсем пуст, сначала нажмите предложение **uploading an existing file**.
4. Перетащите содержимое распакованной папки `AgroKontrol` в окно загрузки, включая папки `src` и `supabase`. Убедитесь, что структура сохранена и файл `package.json` лежит **в корне** репозитория.
5. Не загружайте `node_modules`, `.env.local` и файлы с паролями. Файл `.env.example` допускается — он не содержит секретов.
6. Нажмите **Commit changes**. После загрузки проверьте, что в репозитории видны `src/App.jsx`, `src/styles.css`, `supabase/schema.sql`, `package.json`.
7. Если браузер телефона не позволяет загрузить папки целиком, выполните этот шаг на Mac или Windows, а дальше можете работать с iPhone.

### Шаг 6. Опубликовать сайт на Vercel
1. Откройте https://vercel.com/new и войдите через GitHub.
2. В разделе **Import Git Repository** найдите репозиторий с файлом `package.json` и нажмите **Import**.
3. **Project Name:** `agrokontrol`. **Framework Preset:** `Vite`. **Root Directory:** `./` (если `package.json` лежит в корне).
4. **Build Command:** `npm run build`; **Output Directory:** `dist`. Vercel может подставить их автоматически.
5. В разделе **Environment Variables** добавьте:
   - Name: `VITE_SUPABASE_URL`; Value: ваш Project URL из Supabase.
   - Name: `VITE_SUPABASE_PUBLISHABLE_KEY`; Value: ваш Publishable key из Supabase.
6. Переменные нужны для **Production**; при необходимости также для **Preview**.
7. Нажмите **Deploy**. При успешной сборке получите адрес вида `https://agrokontrol-....vercel.app`.
8. Откройте этот адрес. Должна появиться форма входа. Войдите учётной записью администратора из шага 3.
9. При необходимости в Supabase откройте **Authentication → URL Configuration**, установите свой Vercel-адрес как **Site URL** и добавьте его в разрешённые Redirect URLs для будущих почтовых сценариев.

### Шаг 7. Проверить работу (без настоящих финансовых данных)
1. Создайте тестового клиента «Тест Клиент»: площадь **3000 м²**, тариф **7 ₽/м²**, визитов **4**.
2. Система создаст месячное начисление **21 000 ₽**. Одна доля — **5 250 ₽**.
3. В разделе «Оплаты» внесите **5 250 ₽**, способ «Наличные».
4. В разделе «Календарь визитов» выберите подходящую неделю того же месяца и нажмите **Сформировать автоматически**. После подтверждения появится визит по оплаченному объёму.
5. Войдите как агроном: оплаты видны, но кнопок изменения финансов нет. Попробуйте изменить статус визита.
6. Проверив работу, удалите тестовые записи через Supabase Table Editor, строго с учётом связей (сначала платежи, потом визиты и начисления, затем клиент) либо оставьте с пометкой «Тест», чтобы не спутать с реальными данными.

## Работа на iPhone
- После публикации откройте адрес `.vercel.app` в Safari.
- Нажмите «Поделиться» → «На экран Домой». Получится ярлык AgroKontrol, который открывает сайт как приложение.
- iPhone, Mac и обычный PC будут видеть одни и те же данные Supabase; нужен интернет.
- **Важно:** создать исходный GitHub-проект и провести первоначальную настройку удобнее с компьютера. После настройки пользоваться можно с телефона.

## Работа на Mac и Windows локально
Требуется Node.js LTS (с https://nodejs.org) и доступ к интернету при установке.
1. Распакуйте папку AgroKontrol.
2. Откройте её в VS Code или в терминале.
3. Создайте рядом с `package.json` файл `.env.local` с двумя переменными по примеру `.env.example`.
4. Выполните:

```bash
npm install
npm run dev
```

5. Перейдите по адресу, который напишет Vite (обычно http://localhost:5173).
6. Для проверки сборки: `npm run build`.

## Ежемесячная работа
1. Администратор выбирает месяц и нажимает **Начислить месяц**, если начисления ещё не были созданы. Повторное нажатие не дублирует начисления.
2. По мере поступления денег записывает платежи (наличные/банк) в нужное начисление. Для старого долга сначала создаёт отдельную запись в разделе «Долги».
3. В начале недели выбирает нужную неделю календаря и нажимает **Сформировать автоматически**. Программа предложит визиты по внесённым платежам. Проверяет дни, время, дорожные переезды; при необходимости переносит визиты.
4. Агроном открывает тот же сайт и отмечает, был визит или консультация.
5. Администратор смотрит отчёты, экспортирует копию данных и хранит её защищённо.

## Права и безопасность
- Все таблицы защищены **Row Level Security**; без записи в `profiles` клиент не получает доступа.
- Роль `admin`: чтение всех данных, изменение клиентов, начислений, оплат, расходов, визитов.
- Роль `agronomist`: чтение финансов и клиентов, планирование/отметка визитов, но **нет записи в финансовые таблицы**.
- Триггер платежей не позволяет превысить сумму начисления. Изменения записываются в `audit_log`, просматривать его можно через Supabase SQL Editor (для администратора БД).
- Реальные персональные и платёжные данные хранятся в **Supabase**, а не в GitHub или статическом коде.
- Проект не был проверен с вашей настоящей базой до настройки; сначала пройдите тестовый сценарий. Для значительного масштаба нужны пагинация и дополнительные тесты.
